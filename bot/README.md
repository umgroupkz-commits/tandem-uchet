# Бот приёма заказов Енешки

Клиент пишет в WhatsApp Енешки, бот (Claude Sonnet 5.5) собирает заказ по меню учёта, показывает итог
и после «да» клиента создаёт заказ в учёте. Каждый заказ подтверждает человек: карточка приходит в
Telegram-группу и на кассу, вкладка «Заказы». Жалобы, просьбы позвать человека и всё непонятное бот
передаёт продавцу.

Спецификация: `docs/superpowers/specs/2026-10-16-eneshka-order-bot-design.md`, план: `docs/superpowers/plans/2026-10-16-eneshka-order-bot-b-bot.md`.

## Что где

| Файл | Что делает |
| --- | --- |
| `main.ts` | запуск: база, клиенты, сервер, наблюдатель (10 с), напоминания (60 с) |
| `src/dialog.ts` | ход разговора: системная часть (правила, меню, частые вопросы), инструменты, итог |
| `src/menu.ts` | текст меню и правил из `bot_menu` учёта, проверка корзины |
| `src/inbound.ts` | вебхук «Узла»: подпись, склейка сообщений, передача человеку, пауза |
| `src/telegram.ts` | карточки заказов и кнопки статусов, команды группы |
| `src/watcher.ts` | журнал событий заказов учёта: сообщения клиенту о статусах, напоминания продавцу |
| `sql/` | схема `bot` в своей базе Postgres (создаётся сама при старте) |
| `eval/` | 30 эталонных разговоров и снимок меню; прогон платный |
| `deploy/` | запуск на сервере рядом с «Узлом»: compose, заготовка `bot.env`, `vpisat.sh`, сценарий дня установки |

Что бот знает, задаётся в учёте, а не в коде: бэк-офис → «Заказы клиентов» → «Меню заказов» (бот видит
только позиции с отметкой «цена сверена») и «Настройки» (часы, сроки, доставка, оплата, Kaspi, частые вопросы).

## Проверка

- `deno task test` - 153 теста без сети и без денег, включая сверку эталонов со снимком меню.
- `deno task check` - проверка типов.
- `deno task eval` - 30 разговоров на настоящей модели, около $2 за прогон: только по «да» Андрея.
  Нужен `ANTHROPIC_API_KEY` в окружении. Снимок меню `eval/menu.json` переснимать после больших правок меню.

## Переменные окружения (`bot.env` на сервере, права 600)

Значения ключей - только в этом файле на сервере: не в репозитории, не в чате, не в журнале.

| Имя | Откуда |
| --- | --- |
| `UZEL_BASE_URL` | адрес «Узла» Енешки |
| `UZEL_API_KEY` | окно «Узла» → «Ключи для программ» → «Выдать ключ», галочка «Этот ключ - бот» |
| `UZEL_WEBHOOK_SECRET` | пишет `scripts/register.ts` сам |
| `UCHET_API_URL` | `https://qeehxcnnuzuwskznhdyg.supabase.co/functions/v1/uchet` (пока учёт на Supabase) |
| `UCHET_SERVICE_KEY` | пишет `scripts/bot-key.ts` сам; его отпечаток - в настройку учёта `bot_key_hash` |
| `ANTHROPIC_API_KEY` | ключ Anthropic Андрея |
| `BOT_MODEL` | необязательно, по умолчанию `claude-sonnet-5-5` |
| `TELEGRAM_BOT_TOKEN` | @BotFather, бот Енешки |
| `TELEGRAM_WEBHOOK_SECRET` | любая случайная строка |
| `TELEGRAM_OWNER_ID` | числовой id Андрея в Telegram (команды группы принимаются только от него) |
| `PUBLIC_BASE_URL` | адрес бота снаружи, например `https://bot.<домен Енешки>` |
| `DATABASE_URL` | задаёт `deploy/docker-compose.yml`, руками не нужен |

## Управление из Telegram-группы (только владелец)

- `/here` - карточки заказов приходят в эту группу.
- `/allow` ответом на сообщение сотрудника - он может нажимать кнопки; `/disallow` - забрать; `/team` - список.
- `/pause` - бот на паузе: новые разговоры сразу передаются продавцу; `/resume` - снова принимает заказы.

## Журнал

Таблица `bot.journal` в базе бота: входящие, ответы, ошибки (телефоны - маской).
Посмотреть: `docker compose exec db psql -U bot -d bot -c "select at, kind, text from bot.journal order by at desc limit 50"`.
