# Запуск учёта: проверка, рабочая касса, обновление из iiko

Три части. Первые две можно делать в любом порядке и заранее; обновление из iiko - последним, накануне старта,
иначе данные успеют устареть (между 04.09 и 17.10.2026 в iiko поменялись 127 техкарт, после 23.10 - ещё 54).

## 1. Проверка работоспособности (делают сотрудники клиента)

- План: https://umgroupkz-commits.github.io/tandem-uchet/proverka-kassy.html - уроки (около 45 минут), смена без
  подсказок (15 шагов с отметками), отчёт. Отметки живут в браузере того, кто проходит.
- Вход в обучение - код обучения на странице «Обучение» (test.html). Код даём в сообщении, на страницы не пишем:
  они публичные. Проверить, что код живой: `training_info` с кодом отдаёт `creds`.
- Учебная касса пробивает чеки на тестовом стенде Webkassa (devkkm, ОФД тестовый) - в налоговую ничего не уходит.
- Отчёт сотрудника - снимок или текст раздела «Отчёт» с плана. Что не прошло - разбираем до запуска.
- Сами перед этим: `node tools/fiscal-unit.mjs` (без сети) и `node tools/fiscal-e2e.mjs` (стенд).

## 2. Подключение рабочей кассы Webkassa

Настройки Webkassa в Vault - два набора (миграция 0060): `webkassa_test_*` - тестовый стенд для учебной кассы
(записан 06.11.2026), `webkassa_*` - общий, для остальных касс. Учебная касса без тестового набора при боевом
общем наборе не пробивает ничего (защита в `pickConfig`, supabase/functions/uchet/fiscal.js).

Что нужно:
1. Боевой доступ интегратора: Webkassa даёт его после совместного теста с их командой (docs/webkassa-api.md).
   Это наша часть, договориться с менеджером Webkassa.
2. От клиента:
   - касса в их кабинете Webkassa: заводской номер ЗНК вида `SWK…` для каждой точки, где пробиваем;
   - пользователь Webkassa для учёта (email и пароль) с доступом к этим кассам. Пароль - не в переписку: пусть
     впишет сам в файл или продиктует, в чат и журнал не попадает;
   - решение по кассе iiko: одна касса Webkassa - одна смена и одни наличные. Если сейчас iiko пробивает через ту же
     кассу, в день перехода iiko на ней выключают, иначе наш Z-отчёт закроет смену и изымет наличные iiko;
   - ставка НДС в чеке (без НДС, 12 или 16) и ширина ленты принтера (58 или 80 мм).
3. Файл `data/webkassa-rabochaya.local` (вне git), строки:
   `WEBKASSA_BASE=` боевой адрес из документации кабинета, `WEBKASSA_API_KEY=` боевой ключ интегратора,
   `WEBKASSA_LOGIN=`, `WEBKASSA_PASSWORD=` - пользователь клиента.
4. `node tools/webkassa-config.mjs --rabochaya` - откажет, если в файле адрес стенда или нет тестового набора.
5. Бэк-офис → «Склады» → таблица точек → точка: флажок «пробивать фискальные чеки (Webkassa)», заводской номер
   кассы, НДС в чеке, ширина чековой ленты. С этой минуты точка пробивает;
   чеки, сохранённые раньше, остаются «до фискализации» (points.fiscal_since, 0058) и смену не держат.
6. Проверка: на кассе точки «X-отчёт» - номер смены и наличные рабочей кассы; первый чек небольшой, QR открывает
   его на сайте ОФД; учебная касса - тот же X-отчёт, должна остаться на стенде.

Откат: выключить «Фискальный чек» у точки - касса работает как раньше, без налоговой.

## 3. Обновление из iiko и старт

Накануне старта, вечером, когда в iiko больше не правят.

1. Попросить у клиента выгрузки (страница https://umgroupkz-commits.github.io/tandem-uchet/vygruzki-iiko.html):
   «Сводный прейскурант» и «Расширенную оборотно-сальдовую ведомость» по каждому складу на день старта.
2. Холостая проверка: `node tools/iiko-obnovlenie.mjs proverka` (около 15 минут: справочники и изменившиеся
   техкарты). В базу ничего не пишет; печатает новые, переименованные, сменившие единицу или тип, удалённые
   позиции и изменённые техкарты. Посмотреть, нет ли сюрпризов (массовая смена единиц, удаления).
3. Копия таблиц базы (служебный ключ DDL не умеет - через SQL Supabase):
   ```sql
   create schema backup_ГГГГММДД;
   revoke all on schema backup_ГГГГММДД from public, anon, authenticated;
   create table backup_ГГГГММДД.items as table tandem.items;
   create table backup_ГГГГММДД.item_groups as table tandem.item_groups;
   create table backup_ГГГГММДД.counteragents as table tandem.counteragents;
   create table backup_ГГГГММДД.stores as table tandem.stores;
   create table backup_ГГГГММДД.charts as table tandem.charts;
   create table backup_ГГГГММДД.chart_lines as table tandem.chart_lines;
   create table backup_ГГГГММДД.item_prices as table tandem.item_prices;
   ```
   Старые копии (backup, backup_20261017, backup_20261023, backup_20261030) удалять только с согласия Андрея.
4. `node tools/iiko-obnovlenie.mjs zapusk` - справочники, штрихкоды (вид `gtin`, 0059), техкарты и цены закупа;
   около часа, лучше в фоне. Прежние справочники iiko - в `data/iiko/snap_<дата>`. Правленное в бэк-офисе
   (позиции и карты с source не iiko, штрихкоды с gtin_source 'office') перенос не трогает.
5. Бэк-офис → Номенклатура → «Загрузить прейскурант» - файл из п.1. Особенно позиции, сменившие единицу.
6. Остатки: по каждому складу инвентаризация с флажком «Ввод начальных остатков» → «Загрузить факт из файла» -
   ведомость этого склада.
7. Проверки:
   - бэк-офис → «Готовность»: цены, себестоимость, техкарты, дубли, НТИН/штрихкоды, склады у точек;
   - сверка с копией: позиции source=office не изменились; меню бота Енешки (tandem.order_menu) - что
     переименовано, снято с продажи или сменило единицу, сообщить чату бота;
   - `node tools/tour-run.mjs role:kassa` и другие роли - уроки проходят на живой базе;
   - `node tools/office-smoke.mjs` и `tools/smoke-live.ps1`, если известен PIN admin.
8. После старта - в README строка «последнее обновление из iiko» с датой.

## Что берём у клиента (сводно)

- Отчёт по плану проверки кассы.
- Поправки в iiko до обновления: цены продажи у позиций без цены, себестоимость сырья без цены закупа, техкарты
  блюд без карты, дубли названий, штрихкоды с упаковки у товаров для перепродажи (по штрихкоду Webkassa сама
  находит НТИН). Списки - «Готовность» в бэк-офисе.
- Сотрудники: имя, должность, точка, телефон - для учёток (бэк-офис → Пользователи; кассирам - имена в точке).
- Какой склад у какой точки (сейчас у 25 из 26 складов точки нет, у 5 точек нет склада).
- Данные рабочей кассы - раздел 2.
- В день старта - прейскурант и оборотки по складам.
