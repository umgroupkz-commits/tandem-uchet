# Фискализация кассы через Webkassa и НТИН - устройство

Решение клиента 30.10.2026: касса программы пробивает фискальные чеки и передаёт НТИН товаров для
перепродажи (обязательно с 01.07.2026). Клиент уже работает с Webkassa в связке с iiko. Контракт API -
docs/webkassa-api.md.

## Принципы

- **Выключено, пока не включат.** У точки флажок «пробивать фискальные чеки» и заводской номер кассы
  Webkassa (ЗНК). Без флажка касса работает как сейчас. Точка переключается с iiko целиком в один день:
  одну продажу фискализирует одна система.
- **Сначала наш чек, потом фискальный.** Чек сохраняется у нас как сейчас (`check_save`, очередь по `uid`),
  затем отдельное действие `fiscal_check` пробивает его в Webkassa. Номер операции для Webkassa
  (`ExternalCheckNumber`) - `uid` чека: повтор после обрыва связи не создаёт второй фискальный чек.
- **Тело чека строит база.** `fiscal_prepare` в гейте проверяет код точки и собирает запрос из строк
  чека: позиции (название, код, количество, цена, скидка, единица, НТИН/GTIN, признак товар/услуга),
  НДС по настройке точки, оплаты (наличные 0, карта 1, Kaspi QR и перевод - мобильный платёж 4).
  Так правила формирования чека проверяются SQL-сценариями, как всё остальное.
- **Ключи - только на сервере.** API-KEY, логин и пароль Webkassa - в секретах Edge Function (и в
  окружении своего сервера). Браузер их не видит. Запись фискального результата - функция, доступная
  только серверу (service role), иначе касса могла бы записать себе любой фискальный признак.
- **Один модуль на два сервера.** `supabase/functions/uchet/webkassa.js` (без зависимостей) подключают
  Edge Function и `server/proxy.mjs`. `WEBKASSA_MODE=sim` - имитация для песочницы и тестов.

## Операции

| В кассе | В Webkassa |
|---|---|
| Пробить чек | `check`, OperationType 2 (продажа) |
| Отменить пробитый чек | `check`, OperationType 3 (возврат продажи) с `ReturnBasisDetails` исходного |
| Исправить пробитый чек | нельзя: продавец отменяет его (чек возврата) и пробивает новый |
| Вкладка «Смена» → X-отчёт | `XReport` |
| Закрыть смену | `ZReport` (Webkassa требует закрывать смену не реже раза в 24 часа) |
| Расход из кассы | `MoneyOperation`, изъятие (1) |
| Печать чека | `Ticket/PrintFormat` (58 или 80 мм по настройке точки) → печать из браузера |

## Данные

- `points`: `fiscal_enabled`, `fiscal_cashbox`, `fiscal_vat` (ставка НДС, пусто - без НДС),
  `fiscal_paper` (58/80).
- `items`: `ntin`, `gtin`, `position_type` (0 товар, 2 услуга; по умолчанию товар).
- `checks`: `fiscal_status` (нет / пробит / ошибка / возвращён), фискальный признак, РНМ, время, смена,
  ссылка на чек, признак автономного режима, текст ошибки, число попыток; то же для возврата.
- `daily_reports`: результат Z-отчёта.
- «Готовность»: товары на продаже без НТИН (для точек с включённой фискализацией).

## Нет связи

Чек остаётся у нас «не пробит» и виден кассиру; повтор - кнопкой и автоматически при появлении связи.
Порядок для кассира при долгом обрыве (приложение Webkassa на телефоне, WK.LocalServer) - решить с
клиентом.

## Открытые вопросы к клиенту и бухгалтеру

Ставка НДС и юрлица точек, товар/услуга для блюд, ОКЭД производства (НТИН на свою продукцию),
возвраты после закрытия смены, смешанная оплата, округление наличных, бумажный или электронный чек,
чеки заказов бота (метод курьерских заказов). Список вопросов - в переписке 30.10.2026.

## Сделано (сборка 26, 30.10.2026)

Проверено на тестовой кассе Webkassa через рабочий сервер и экран кассы: продажа, повтор без второго
чека, печатная форма с QR (58 мм), запрет правки пробитого, отмена = чек возврата, отказ Webkassa (неверный
номер кассы) - понятное сообщение, пометка и автоповтор при входе, X-отчёт, Z-отчёт с закрытия смены и защита
«сначала пробейте все чеки», повторный Z (код 12) - не ошибка. Бэк-офис: настройки точки и НТИН в карточке
(0054), проверка «Готовности» (0055 - без учебных точек).

## Отложено

- Изъятие наличных (`MoneyOperation`): без него «Наличные в Webkassa» копят прошлые смены.
- Кассир в фискальном чеке - пользователь Webkassa, а не продавец из нашей кассы.
- Правка чека в те секунды, пока он пробивается: фискальный чек выйдет по прежним строкам. Окно короткое;
  закрыть - пометкой «пробивается» на время запроса.
- Чеки заказов с доставкой: когда пробивать (при оплате или при доставке) - вопрос к бухгалтеру.
- Загрузка НТИН из штрихкодов iiko.
- Боевые ключи Webkassa и совместная проверка с ними - когда клиент даст доступ к кабинету.
