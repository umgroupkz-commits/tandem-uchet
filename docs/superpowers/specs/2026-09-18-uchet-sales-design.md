# Подпроект 4 «Продажи как документы» — спецификация

Дата: 18 сентября 2026. Писалась без обсуждения с Андреем (он попросил работать автономно):
решения приняты по данным и по поведению iiko, каждое допущение помечено **[допущение]** —
их надо подтвердить после тестирования.

## Цель

Дневной отчёт точки (экран `index.html`, таблицы `daily_reports` + `sale_lines` +
`takeout_lines`) сам порождает складской документ «Продажа», и остаток склада точки
уменьшается на проданное. Без этого склад знает только приходы, перемещения и
инвентаризации, и расчётный остаток не с чем сравнивать.

## Решения

1. **Один документ на отчёт.** Тип `sale`, номер `ПД-ГГГГ-NNNNNN`, дата = дата отчёта,
   склад-источник = склад точки по умолчанию (`points.default_store_id`),
   `source_kind = 'daily_report'`, `source_id = id отчёта`. Контрагента нет.
2. **Что продано.** По каждой позиции: `sale_lines.qty` (режим «по позициям») плюс
   `takeout_lines.issued − returned` (режим «вынос»); строки без кода номенклатуры не
   участвуют; сумма по позиции ≤ 0 (возвраты перекрыли продажу) — позиция пропускается;
   выключенные позиции и услуги пропускаются. Цена строки — средневзвешенная цена продажи
   (для выручки в карточке), это не себестоимость.
3. **Что списывается** — как в iiko (проверено по обороткам клиента: колонка «Продажи»
   заполнена у сырья, а не у готовых блюд): у позиции есть действующая на дату отчёта
   техкарта — списываются ингредиенты карты (брутто × кол-во ÷ выход, один уровень, как
   в производстве; полуфабрикат-ингредиент списывается сам); карты нет — списывается сама
   позиция. Себестоимость — средняя склада, как у списания. Сумма документа — себестоимость
   проданного. **[допущение]** один уровень раскрытия: полуфабрикаты на точке считаются
   заготовленными заранее (актом производства), а не варятся «под продажу».
4. **Когда.** Сразу при сохранении отчёта точкой (`tandem_api.save_report`) —
   синхронизация `tandem.sale_sync(report_id)`: документа нет — создать и провести; есть и
   строки те же — ничего; есть и строки изменились — отменить проведение, переписать,
   провести; строк не осталось — отменить и удалить. Ошибка синхронизации никогда не ломает
   сохранение отчёта: отчёт — деньги точки, склад вторичен.
5. **Точка без склада** — документ не создаётся, отчёт виден в бэк-офисе как «у точки нет
   склада». После привязки склада — кнопка «Провести продажи за период».
6. **Отчёт изменён после инвентаризации** этого склада — документ не пересчитывается
   (отмена запрещена правилом подпроекта 3), в документ пишется пометка `sync_note`, в
   бэк-офисе видно «отчёт изменён после инвентаризации». **[допущение]** так и должно быть:
   инвентаризация зафиксировала факт, переписывать задним числом нельзя.
7. **Руками документ продажи не правится**: нельзя создать, сохранить, провести, отменить,
   удалить — только пересчитать из отчёта. Права: `doc:sale` — просмотр у всех складских
   ролей, «пересчитать» — администратор, собственник, бухгалтер.
8. **Бэк-офис**: в журнале склада — тип «Продажа»; карточка только для чтения: проданное
   (кол-во, цена продажи, выручка) и «Списано по техкартам»; вкладка «Продажи» —
   отчёты точек за период с состоянием (проведён / нет склада / нет продаж /
   пометка) и кнопка «Провести продажи за период».
9. **Дашборд собственницы** (`raw_usage`) берёт техкарту на дату отчёта, а не на сегодня
   (отложенное замечание подпроекта 1).

## Проверка

- дымовой тест: отчёт точки с блюдом с картой и товаром без карты → документ `sale`
  проведён, ингредиенты и товар списаны; повторное сохранение без изменений — тот же
  документ, движения не задвоены; изменение количества — пересчёт; обнуление — документ
  удалён; точка без склада — документа нет; ручные действия над продажей — отказ;
  отчёт после инвентаризации — пометка;
- маршрут проверки: учебная точка → отчёт → продажа в журнале склада → остатки.

## Уточнения при реализации (18.09.2026)

- Независимое ревью ветки нашло пять проблем до выпуска, все исправлены в 0023 и проверены
  тестом: сбой синхронизации при сохранении отчёта оставляет пометку («устарела»); продажа не
  проводится, если инвентаризация склада **более поздним днём** уже учла проданное — документ
  остаётся черновиком с пометкой (иначе двойное списание); лок отчёта в `sale_sync` и единый
  порядок блокировок расхода; пересчёт — до месяца, с `lock_timeout` и подтранзакцией на отчёт;
  кладовщик с привязкой видит только точки своих складов (и их деньги), список требует `doc:sale`.
- **[допущение]** инвентаризация в тот же день, что и отчёт, считается утренней (до продаж) и
  продажу не блокирует. Если на точках считают вечером после закрытия — правило надо сменить.
- Пометка «без техкарты» больше не держит документ: пересчёт проводит его заново, когда карта
  появилась; выключенные позиции из отчёта перечисляются в пометке.
- Дымовой тест перенесён на служебную выключенную точку `zz_test` (раньше тест привязывал
  тестовый склад к настоящей точке «Аян»).
- Исправление 0024: псевдоним `c` в запросе расхода совпадал с переменной цикла — продажа блюда
  с картой падала; найдено тестом до выпуска.
- Сделано сверх спецификации: оборотная ведомость склада (вкладка «Ведомость») — для сверки с iiko.
