# Миграции базы

Файлы применяются по порядку номеров к схеме `tandem` (Supabase, проект qeehxcnnuzuwskznhdyg)
инструментом apply_migration; имя миграции = имя файла без расширения.

**Чего здесь нет.** Схема до 0001 создана миграциями в панели Supabase
(`tandem_init_schema` … `cash_shift_open_cash_manual`) и в репозитории отсутствует.
Поэтому `psql -f` по этим файлам на пустую базу схему не поднимет. Путь переезда на
собственный сервер — `pg_dump` схемы `tandem` с боевой базы, восстановление на новом
сервере, затем прокси (замена Edge Function) и nginx. Файлы 0001+ — дельта: их можно
по порядку применить на копию базы, чтобы догнать её до текущего состояния.

Роли `anon`, `authenticated`, `service_role` есть только в Supabase, поэтому все
`grant`/`revoke` по ним обёрнуты в `do $$ ... if exists (select 1 from pg_roles ...)`.
`revoke ... from public` оставлен снаружи: PUBLIC есть в любом Postgres.
Обёртку добавили задним числом (замечание I4), 0003–0005 при этом не переприменялись —
в базе поведение то же, история миграций отличается от файлов только этой обёрткой.
